# QiuForm

给任意网页配一个数据接口。

大模型几秒钟就能写出一张漂亮的互动网页，但学生填完就没了。QiuForm 让每个任务
拥有一个**可写可读的公开接口地址** —— 任何网页把数据 POST 过来，都会汇总到
同一个后台，能看、能导出、能实时展示。

```
POST /api/<任务编号>          写入（JSON / 表单 / multipart 带文件）
GET  /api/<任务编号>          读出最近几条
GET  /api/<任务编号>/all      读出全部
```

## 快速开始

```bash
pip install -r requirements.txt
python run.py
```

打开 <http://127.0.0.1:8000/>，注册一个账号就能用了。

常用参数：

```bash
python run.py --port 9000            # 换端口
python run.py --host 127.0.0.1       # 只允许本机访问
python run.py --debug                # 开发模式，改代码自动重启
python run.py --dev                  # 用 Flask 自带服务器，不用 waitress
```

> 没有装依赖也能跑：把包放进项目内的 `.vendor/` 目录即可，`run.py` 会自动识别。

## 四个页面就够用

| 页面 | 做什么 |
| --- | --- |
| **概览** | 接口地址、二维码、最近提交。把地址复制走就能开始收数据 |
| **页面** | 上传你做好的 HTML，得到公开网址和二维码；也能传它用到的 css / js / 图片 |
| **数据** | 提交记录逐条可查、可删、可分页；导出 CSV / JSON |
| **设置** | 改名字和简介、切换读写模式、删除任务 |

## 界面

- **亮色 / 暗色两套主题**，默认跟随系统，右上角可以手动切换，选择记在本地。
- **响应式**：窄屏下导航收成图标、数据表变成卡片列表、宽表格横向滚动。
- 图标是内联 SVG，字体走系统栈，整站**不依赖任何外部 CDN** —— 断网、
  校园内网都能正常显示。
- 样式集中在 `qiuform/static/app.css`，开头是一组 CSS 变量，
  改配色只动那一处。

## 核心设计

### 一个任务 = 一个接口地址

任务的编号（`apiid`）就是公开标识，创建后固定不变。地址不鉴权、不加密，
谁拿到都能读写 —— 这是**刻意的取舍**，为的是让任何大模型生成的代码
"接上就能用"，不用处理 Token、Cookie、签名这些事。

风险由**读写模式**兜底：

| 模式 | 含义 | 用在哪 |
| --- | --- | --- |
| 可读可写 | 默认 | 收数据，同时让页面读回去做实时统计 |
| 只读 | 能读不能写 | 数据收完了，但还要继续展示 |
| 只写 | 能写不能读 | 问卷这类：能提交，但读不到别人的回答 |
| 已关闭 | 读写全拒绝 | 不再使用的任务 |

### 不预设字段

没有表结构，没有字段定义。提交上来什么就原样存什么，后台的表格列是
**根据实际收到的字段自动长出来的**。代价是没法用 SQL 直接分析，收益是
不用先想清楚要收什么 —— 后续拿大模型去分析就行。

### 页面托管 + 地址自动改写

把 HTML 传上来时，服务端会扫描里面的接口地址并替换成本任务的地址：

- `https://某台服务器/api/旧编号` → `/api/新编号`
- `/api/旧编号` → `/api/新编号`

改成**相对地址**而不是绝对地址，换域名、换端口都不用重新改页面。
`examples/课堂反馈.html` 里写着 `/api/YOUR_TASK_ID_HERE`，传上去就会被
自动替换成该任务的真实地址。

### 文件上传

同一个接口也收文件（`multipart/form-data`）。文件存到
`data/files/<任务编号>/`，数据里只留一个 `attachment` 路径，
所以页面和看板可以直接把它塞进 `<img src>` 显示。

```bash
curl -X POST http://127.0.0.1:8000/api/<任务编号> \
  -F "category=橡皮" -F "file=@photo.jpg"
```

文件字段名随便取，服务端会把保存后的路径写成 `attachment` 字段；
一次传多个文件时它是数组。任务「概览」页里有一段可直接复制的提示词。

现成的例子见 `examples/图片采集.html` —— 选分类、拍照或选图、
前端压缩到 2MB 再上传，传到任务里就能用（里面的接口地址会被自动改写）。

> 提示词里记得加一句「**不要将文件编码为 Base64 形式**」。否则模型很可能
> 把图片转成一长串 base64 塞进 JSON，体积膨胀 1/3 还会超限。

## 目录结构

```
QiuForm/
├── run.py                     启动入口
├── requirements.txt
├── qiuform/
│   ├── __init__.py            应用工厂、错误处理
│   ├── db.py                  SQLite 连接、建表、全部数据存取
│   ├── security.py            密码哈希（scrypt）、登录态、CSRF
│   ├── auth.py                注册 / 登录 / 账号设置
│   ├── tasks.py               任务、页面托管、数据、设置
│   ├── public.py              公开访问：/p/ 页面与 /files/ 附件
│   ├── api.py                 数据接口（核心）
│   ├── storage.py             文件落盘、接口地址改写
│   ├── multipart.py           multipart 解析（自己写的，无依赖）
│   ├── qrcode_gen.py          二维码生成（自己写的，无依赖）
│   ├── templates/             Jinja 模板
│   └── static/                样式与脚本
├── examples/                  示例网页 + 灌数据脚本
├── tests/                     端到端测试
└── data/                      运行期生成：数据库、上传的页面和附件
```

依赖只有 Flask 和 waitress。二维码和 multipart 解析都是自己实现的
（标准库的 `cgi` 模块在 Python 3.13 已被移除）。

## 测试

```bash
python run.py --port 8000          # 另开一个终端把站点跑起来
python tests/smoke_test.py
```

65 项端到端断言，覆盖注册登录、CSRF、任务创建、接口读写、跨域头、
全量读取限流、多模态上传（含字节级校验）、HTML 托管与地址改写、
路径穿越防护、二维码、导出、四种读写模式、越权访问 —— 跑完会把自己
创建的任务删掉。

二维码另外有一份对照测试，拿参考实现逐模块比对矩阵：

```bash
pip install qrcode --target /tmp/qrref
PYTHONPATH=/tmp/qrref python tests/verify_qrcode.py
```

## 安全说明

这个设计**不追求安全性**，它追求的是"接得上"：

- 数据接口不鉴权、不加密，拿到地址就能读写。
- 密码用 scrypt 加盐哈希存储，会话 Cookie 是 HttpOnly + SameSite=Lax，
  所有网页表单都有 CSRF 校验。
- 服务器文件名一律重新生成，页面按白名单登记后才对外服务，挡住路径穿越。

**不要用它收集敏感信息。** 涉及身份证号、联系方式、成绩这类数据时，
至少先脱敏，或者换成有完整鉴权体系的系统。

## 备份

所有数据都在 `data/` 目录里：

| 文件 | 内容 |
| --- | --- |
| `data/qiuform.db` | 账号、任务、提交记录 |
| `data/pages/<编号>/` | 上传的网页文件 |
| `data/files/<编号>/` | 接口收到的附件 |
| `data/secret_key` | 会话密钥（丢了所有人要重新登录） |

整个目录拷走就是一份完整备份。
